## Visitor controls and data boundaries

- The localized panel sits in normal document flow at the start of `main`, before the tour. It uses existing colors/type/buttons, equal 48px actions and safe-area padding. It does not overlay the 3D scene or contact actions. The footer reopens it with keyboard focus on Refuse; no focus trap or automatic focus on first arrival.
- No Microsoft script or request is initiated before explicit acceptance. Refusal preserves the portfolio. A valid choice is stored in `localStorage` under the new `portfolio.analytics.v1` key for 90 days; invalid, future or expired records cannot grant consent. DNT/GPC override stored acceptance. Storage failure means no remembered grant on subsequent pages; refusal also attempts removal of a stale grant if writing fails.
- A single asynchronous SDK is inserted only on exact `https://ojoaovsousa.pages.dev/{pt-br,en,es}/` URLs without query or fragment. Direct reading, policies, missing/error routes, branch/deployment aliases and other hosts cannot load it. Referrers must be HTTP(S), without userinfo/query/fragment; same-origin referrers must match the known public home/direct/privacy/terms paths, and external referrers must contain only the origin path `/`. Unknown same-origin paths, including 404 entries containing arbitrary text, block the SDK because Clarity can read `document.referrer` and provider URL masking does not cover referrers. These exclusions reduce measurement coverage deliberately; input is never sanitized and forwarded as a tracking parameter.
- Local SDK testing additionally requires a build with exact `ANALYTICS_PREVIEW=true` and a loopback HTTP hostname (`localhost` or `127.0.0.1`). Normal loopback previews expose the controls while keeping SDK loading disabled. This option neither enables indexing nor permits Pages aliases. Do not enable it on the shared preview without approval for synthetic provider QA.
- Acceptance queues `consentv2` with `ad_Storage: denied` and `analytics_Storage: granted` before the tag. Main content also has `data-clarity-mask="true"`; there are no unmask overrides. Masking does not promise anonymity: cookies and pseudonymous identifiers, device/browser information and interactions may still be processed.
- Refusal removes the accessible first-party `_clck`/`_clsk` cookies. If the SDK was loaded, a full reload terminates that page; removing a script element or merely denying cookie consent would leave collection in no-consent mode. Changes to consent storage in another tab also reload an active SDK page. Fragment/history transitions reload active collection; this static site has no History API router. Introducing an SPA router requires a new privacy review before instrumentation.
- CSP retains self defaults, the exact existing noscript style hash, frame/object restrictions and no unsafe-inline/eval. Only script `https://www.clarity.ms`/`https://scripts.clarity.ms`, collection `https://*.clarity.ms`, and Clarity/Bing image endpoints are added to their respective directives. A blocked SDK/cookie operation does not interrupt portfolio controls.

The real privacy policies in PT-BR, English and Spanish explain consent, Microsoft/global processing, revocation and provider retention. Contact channels, terms, no-form behavior and other sensitive rules remain unchanged. The Microsoft retention documentation currently specifies 30 days for replay and 9 months for labeled/favorited sessions, heatmaps and click data; that is distinct from the 90-day local consent preference. Revocation does not retroactively delete data already received. Clarity cannot render the 3D canvas itself; replay is not proof of 3D fidelity, successful contact delivery or conversion.
